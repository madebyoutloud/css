# @outloud/css 4.0

Upgrades a project from `@outloud/css` 3 to 4. Version 3 divided every rem value in the generated CSS by 4, so that a bare number meant px (`p-16` is 16px). That also quartered the theme's sizes: `text-base` came out as 4px and `rounded-lg` as 2px. Version 4 converts only bare numbers, so theme classes render as preset-mini defines them. Number classes don't change.

A project on `@outloud/css` 1 or 2 has a different preset. Move it to 3 first: this guide doesn't cover that.

## Requires

- Node.js 22 or newer for the build.
- UnoCSS `^66.12`.

## Changes

- Theme sizes are no longer divided by 4. What changes, with preset-mini's theme:

  | Class | 3.x | 4.0 |
  | --- | --- | --- |
  | `text-xs` ... `text-9xl`, `fs-xs` ... `fs-9xl` | a quarter | 12px / 16px ... 128px |
  | `text-base` | 4px / 6px | 16px / 24px |
  | `rounded` | 1px | 4px |
  | `rounded-sm` ... `rounded-3xl` | 0.5px ... 6px | 2px ... 24px |
  | `w-`, `h-`, `min-w-`, `max-w-`, `size-` with `xs` ... `7xl` | 80px ... 320px | 320px ... 1280px |
  | `p-`, `m-`, `gap-`, `inset-` with `xs` ... `9xl` | a quarter | 12px ... 128px |
  | `indent`, `indent-xs` ... `indent-3xl` | 2px ... 16px | 8px ... 64px |

  A project theme that sets these keys (`fontSize`, `borderRadius`, `width`, `maxWidth`, `spacing`...) in rem is no longer quartered either. One set in px doesn't change.

- Unchanged: number classes (`p-16`, `gap-24`, `w-320`, `fs-14`, `leading-20`, `rounded-8`, `text-16/24`), `leading-tight` and the other unitless line heights, `rounded-full`, `max-w-screen-*`, `flow`, `container`, `columns`, `col-*`, `pile`, `prose`, the reset and the helpers.
- A number is always px, also when the theme has that number as a key: `theme.spacing['4']` no longer applies to `p-4`. Use names for theme keys.
- A value needs a dash before it. preset-mini also accepts margins, paddings, sizes, gaps, `z`, opacity and font weight without one (`w16`, `mt8`, `p-x4`, `gap16`, `z10`, `op50`, `bg-op50`, `font700`). These generate nothing now. Before, a typography class such as `h1` also got `height: 0.0625rem`.
- Theme colours are CSS variables. The preset writes them on `:root`, and the utilities use them: `bg-brand-500` is `var(--color-brand-500)`, and `bg-brand-500/50` mixes it with transparent. Variable names are the theme path in kebab-case without `DEFAULT`. See "Colours" in the README.
- preset-mini's palette (`red-500`, `gray-100`, `blue-300`...) isn't included any more, only `black`, `white`, `transparent`, `current` and `inherit`.
- `theme('colors.x')` in CSS gives `var(--color-x)` instead of the value.
- `generateColorVariables` is gone: the variables are always written. Its names were the raw path (`--color-text-DEFAULT`); now `DEFAULT` is dropped and camelCase keys are kebab-case.
- `themes` is new: colour sets under a selector, for dark mode or a client's brand. It replaces `unocss-preset-theme` for colours.
- `bg-op-*`, `text-op-*` and the other opacity utilities don't change theme colours, which are variables. Use `/NN` on the colour class.
- The `shortcuts` export is gone. It was empty.
- `sideEffects` is `["*.css"]`, so bundlers that honour it keep `import '@outloud/css/reset.css'`.
- The README and the docs describe how to put the reset, the preflights and the utilities into CSS layers. `reset.css` still ships unlayered: the app picks its layer.

## Steps

### 1. Update the dependency

**Check:** `package.json` has `@outloud/css` `^4`.

- Install `@outloud/css@^4`.
- Update `unocss` and the `@unocss/*` packages to `^66.12` when they are older.

### 2. Find classes that relied on the old sizes

**Check:** the search below finds nothing, or every match is meant to render at its new size.

Search the project's templates, scripts and styles, including `@apply` and `--at-apply`, for theme size classes:

```bash
rg -nP --glob '!node_modules' --glob '!.nuxt' --glob '!.output' --glob '!dist' \
  '(?<![\w.$/-])-?((text|fs)-(xs|sm|base|lg|[2-9]?xl)|rounded(-(t|b|l|r|s|e|tl|tr|bl|br|ss|se|es|ee))?(-(sm|md|lg|[23]?xl))?|(min-|max-)?(w|h|size)-(xs|sm|md|lg|[2-7]?xl)|(p|m)[xytrblse]?-(xs|sm|lg|[2-9]?xl)|gap(-[xy])?-(xs|sm|lg|[2-9]?xl)|indent(-(xs|sm|md|lg|[23]?xl))?)(?![\w/-])'
```

Words like `rounded` can also be a component prop or a variable, as in `<Avatar rounded>` or `:rounded="3"`: skip those.

For each class that is meant to keep its old size, replace it with the px number it rendered as:

| 3.x class | Replace with |
| --- | --- |
| `text-xs` | `text-3/4` |
| `text-sm` | `text-3.5/5` |
| `text-base` | `text-4/6` |
| `text-lg` | `text-4.5/7` |
| `text-xl` | `text-5/7` |
| `rounded` | `rounded-1` |
| `rounded-md` | `rounded-1.5` |
| `rounded-lg` | `rounded-2` |
| `max-w-md` | `max-w-112` |

Other sizes are a quarter of preset-mini's value in px. Most projects meant the new size, since the old one is too small to have been chosen: then nothing changes in the code.

### 3. Add the dash to values without one

**Check:** the search below finds nothing, or only HTML tags and the project's own CSS classes.

```bash
rg -nP --glob '!node_modules' --glob '!.nuxt' --glob '!.output' --glob '!dist' -g '*.{vue,ts,tsx,js,html,css,scss}' \
  '(?<![\w.$/#<-])-?((m|p)a?(-?[xytrblse]|-?[bi][se])?|(min-|max-)?[wh]|size-[wh]|gap(-[xy]|-col|-row)?|z|op(acity)?|[a-z-]+-op(acity)?|font|fw)\d[\d.]*(?![\w/-])'
```

Add the dash to each class: `w16` becomes `w-16`, `mt8` `mt-8`, `z10` `z-10`, `op50` `op-50`, `font700` `font-700`. Skip matches that aren't classes, such as `h1` in a selector or a variable name.

### 4. Check a project theme set in rem

**Check:** `uno.config.ts` and the theme it imports set no size in rem, or the new sizes are intended.

A theme key in rem, such as `fontSize: { body: ['1rem', '1.5rem'] }`, rendered at a quarter in 3.x. Keep the rem value to get its real size now, or divide it by 4 to keep the old rendering.

Theme values that are plain numbers (`container.maxWidth: 900`, `flow.padding: 16`, `grid.gap: 16`) are px and don't change.

### 5. Colours

**Check:** every colour class the project uses comes from its own theme, and `generateColorVariables` is gone from `uno.config.ts`.

- Find colour classes that relied on preset-mini's palette. Search for its names, then add the colours the project uses to its theme, or spread `colors` from `@unocss/preset-mini` into it:

  ```bash
  rg -nP --glob '!node_modules' --glob '!.nuxt' --glob '!.output' --glob '!dist' \
    '(?<![\w-])[a-z-]+-(rose|pink|fuchsia|purple|violet|indigo|blue|sky|cyan|teal|emerald|green|lime|yellow|amber|orange|red|gray|slate|zinc|neutral|stone|light|dark)(-\d+)?(?![\w-])'
  ```

  Matches for a colour the project's theme defines, such as its own `neutral` scale, are fine.
- Remove `generateColorVariables`. Code reading `--color-x-DEFAULT` reads `--color-x` now, and camelCase keys become kebab-case (`--color-cardBg` is `--color-card-bg`).
- Where the project's CSS needs a literal colour from `theme()`, such as a `theme-color` meta tag or a `rgba()` around it, import the value from the theme file instead.
- With `unocss-preset-theme` for dark mode, move its colours to `presetOutloud({ themes: { '.dark': { colors } } })` and remove the preset.
- Replace `bg-op-*` and `text-op-*` on theme colours with `/NN`: `bg-brand bg-op-50` becomes `bg-brand/50`.

### 6. Optional: CSS layers

To put the reset and the preflights into a layer, follow "CSS layers" in the README:

- Declare `@layer reset, vendor, app, uno;` in the first stylesheet.
- Import the reset with `@import '@outloud/css/reset.css' layer(reset);`.
- Set `outputToCssLayers: { cssLayerName: (layer) => (layer === 'preflights' ? 'reset' : 'uno') }` in `uno.config.ts`.

### 7. Verify

- Build the project and open its main pages. Colours render as before, translucent ones included. Text set with `text-*`, corners with `rounded*` and boxes with `max-w-*` theme keys are now their full size. Nothing styled with a dashless class has lost its spacing or size.
