# @outloud/css 3

Upgrades a project from `@outloud/css` 1 or 2 to 3. Version 3 is built on UnoCSS's preset-mini. Number classes still mean px and render as before (`p-16` is 16px), and preset-mini's utilities and variants are added. The rules of 1 and 2 are gone, so a few classes change or disappear, and class names that generated nothing before can generate CSS now.

To reach 4, apply this guide first, then `v4.0.md`. Some 3.x behaviour below (quartered theme sizes, classes without a dash) changes again in 4.

## Requires

- Node.js 20 or newer for the build.
- UnoCSS `^66`: `unocss` and the `@unocss/*` packages.

## Changes

- The rules come from preset-mini. These render as before: `p-*`, `m-*`, `gap-*`, `w-*`, `h-*`, `min-w-*`, `max-w-*`, `min-h-*`, `max-h-*`, `top-*`, `inset-*` with numbers, `fs-*`, `fw-*`, `rounded-*`, `border-*` widths, `z-*`, `opacity-*`, `grid-cols-*`, `col-*`, `offset-*`, `columns`, the breakpoint variants (`md:`, `lt-md:`, `at-md:`) and colour classes (`bg-*`, `color-*`, `text-*`, `border-*`).
- Removed, with no class in 3:
  - `uppercase`, `lowercase`, `capitalize`, `normal-case`. Use `case-upper`, `case-lower`, `case-capital`, `case-normal`.
  - `object-contain`, `object-cover`, `object-fill`, `object-none`, `object-scale-down`, `isolate`, `collapse`.
- `h-screen`, `min-h-screen`, `max-h-screen` are `100vh` only, and `w-screen`, `min-w-screen`, `max-w-screen` are `100vw` only. 2 also wrote `100dvh` and `100dvw`. `h-svh` and `w-svw` are now `100svh` and `100svw`; 2 wrote `100lvh` and `100lvw`.
- `top-full`, `right-full`, `bottom-full`, `left-full` and `inset-full` are `100%`. 2 wrote 9999px.
- `flex-center` also sets `display: flex`. In 2 it only centred.
- Children of `columns` span all columns until they get a `col-*` class. In 2 a child without `col-*` took one column.
- A variant doesn't work on `columns`, `flow` or `container`: `lt-lg:columns` writes a selector that matches nothing. In 2 `lt-lg:columns` worked.
- The generated CSS follows preset-mini's order. When two classes on one element set the same property, a different class can win:
  - `flex` and `inline-flex` come after `hidden`, `grid` and `inline-grid`. `flex hidden` now shows the element, and `flex grid` is a flexbox. In 2 `hidden` and `grid` won.
  - `flex-center` comes after `inline-flex`: `inline-flex flex-center` is now `display: flex`.
  - A side class comes after its axis class. `py-16 pt-8` gives a top padding of 8px and `mx-auto ml-0` a left margin of 0. In 2 `py-*`, `px-*`, `my-*` and `mx-*` won.
- Class names that generated nothing before generate CSS now:
  - preset-mini's utilities and variants, such as `border`, `rounded`, `shadow`, `outline`, `transition`, `transform`, `text-sm`, `hover:*`, `focus:*`, `dark:*` and `!` for important.
  - `container`: `max-width: 932px`, `padding: 16px`, `margin-inline: auto`, `width: 100%` and `container-type: inline-size`. `flow` is a grid layout.
  - preset-mini also accepts sizes and spacing without a dash: `h1` is `height: 1px`, `h6` is 6px, `mt8` is a margin. A project's own `.h1` typography class gets that height too.
  - preset-mini's theme sizes come out at a quarter: `text-sm` is 3.5px, `rounded` 1px, `max-w-md` 112px. So do rem values in brackets: `w-[2rem]` is 8px.
  - preset-mini's palette: `bg-red-500`, `text-gray-400`, `color-green`.
  - From 1 and 2.0.0 to 2.0.2: spacing numbers outside the theme's `spacing` list, odd `w-*` and `h-*` numbers, and number `min-w-*`, `max-w-*`, `min-h-*`, `max-h-*`.
  - From 1: `color-*`, nested theme colours and `/50` opacity.
- The theme is preset-mini's theme plus `grid`, `flow` and `container`. `spacing` (a list of numbers up to 2.0.2), `weight`, `unit` and `baseFontSize` are gone. A `spacing` list breaks spacing: `p-4` reads `spacing[4]` and writes `padding: 8`, with no unit.
- 2.0.5 wrote every theme colour as a variable on `:root` (`--color-primary`). 3 writes them only with `presetOutloud({ generateColorVariables: true })`. The names are the same.
- `toRem` and `toSize` are exported from `@outloud/css/helpers`, not from `@outloud/css`. `toSize` also takes a base.
- `reset.css` is UnoCSS's Tailwind reset now. It differs from the old one:
  - Borders default to `#e5e7eb`, through `--un-default-border-color`. Before they used the text colour.
  - Placeholders are `#9ca3af`.
  - `textarea` resizes vertically. Before it didn't resize.
  - The default sans font stack is shorter, taps don't highlight on iOS, and `dialog` has no padding.
- `helpers.scss` is unchanged. `@outloud/css/reset.css` and `@outloud/css/helpers.scss` keep their paths.
- `presetOutloud` takes preset-mini's options and `generateColorVariables`. `separators` and the `OutloudOptions` type are gone.
- `sideEffects` is `false`, so a bundler can drop `import '@outloud/css/reset.css'` in a script. 4 fixes this.
- From 1: the package is ESM only. It's on npmjs.com from 2.0.2.

## Steps

### 1. Save the generated CSS

**Check:** `uno-before.css` exists and was made with the old version.

Before changing anything, write the CSS the project generates now. It's compared with the new output in step 9.

```bash
pnpm exec unocss '**/*.{vue,html,tsx,jsx,md}' '!**/node_modules/**' '!**/.nuxt/**' '!**/.output/**' '!**/dist/**' \
  --preflights false -o uno-before.css
```

Without the `unocss` package, run `pnpm dlx @unocss/cli@66` with the same arguments. It reads the project's `uno.config.ts`. Don't commit the file.

### 2. Update the dependency

**Check:** `package.json` has `@outloud/css` `^3`, and `unocss` and the `@unocss/*` packages are `^66`.

- Install `@outloud/css@^3`.
- Update `unocss` and the `@unocss/*` packages to `^66` when they are older.
- When the UnoCSS config, the theme or components come from a base layer or a shared package, upgrade it together with every app that uses it. The app resolves `@outloud/css` for that code too.
- When `.npmrc` sends the `@outloud` scope to another registry, check that it serves `@outloud/css` 3. Version 3 is on npmjs.com.

### 3. Remove old theme keys

**Check:** the search below finds no theme key, and `tsc` reports no error for the theme.

```bash
rg -n --glob '!node_modules' -g 'uno.config.*' -g '*theme*.ts' '^\s*(spacing|weight|unit|baseFontSize)\s*:'
```

Remove `spacing`, `weight`, `unit` and `baseFontSize` from the theme. Every number class works without them.

Before:

```ts
export const theme = {
  spacing: [0, 1, 2, 4, 8, 12, 16, 18, 20, 24, 28, 32, 40, 48, 64, 72, 96],
  colors: { primary: '#003fbc' },
} satisfies Theme
```

After:

```ts
export const theme = {
  colors: { primary: '#003fbc' },
} satisfies Theme
```

Matches outside the theme, such as `unit: 'km'` in a model, are fine.

### 4. Import the helpers from `@outloud/css/helpers`

**Check:** the search below finds nothing.

```bash
rg -nP --glob '!node_modules' --glob '!.nuxt' --glob '!.output' --glob '!dist' \
  "\b(toRem|toSize)\b[^;\n]*from\s*['\"]@outloud/css['\"]"
```

```ts
// before
import { toRem } from '@outloud/css'
// after
import { toRem } from '@outloud/css/helpers'
```

`@use "@outloud/css/helpers.scss" as *;` doesn't change.

### 5. Colour variables

**Check:** every `var(--color-*)` the project reads is defined.

Only for 2.0.5, which wrote the variables. Search for them:

```bash
rg -n --glob '!node_modules' --glob '!.nuxt' --glob '!.output' --glob '!dist' 'var\(--color-'
```

Skip the variables the project defines itself, in its own preflight or CSS. When others remain, turn the variables on:

```ts
presets: [presetOutloud({ generateColorVariables: true })],
```

### 6. Replace removed classes

**Check:** the search below finds nothing, or only CSS values such as `text-transform: uppercase` and words that aren't classes.

```bash
rg -nP --glob '!node_modules' --glob '!.nuxt' --glob '!.output' --glob '!dist' -g '*.{vue,html,ts,tsx,js,jsx,css,scss}' \
  '(?<![\w.$/-])(uppercase|lowercase|capitalize|normal-case|object-(contain|cover|fill|none|scale-down)|isolate|collapse|(min-|max-)?[wh]-(screen|svh|svw)|-?(top|right|bottom|left|inset(-[xy])?)-full)(?![\w/-])'
```

Search templates, scripts and styles, including `@apply` and `--at-apply`. Replace each class:

| 2.x class | 3.x class |
| --- | --- |
| `uppercase` | `case-upper` |
| `lowercase` | `case-lower` |
| `capitalize` | `case-capital` |
| `normal-case` | `case-normal` |
| `h-screen`, `min-h-screen`, `max-h-screen` | `h-dvh`, `min-h-dvh`, `max-h-dvh` |
| `w-screen`, `min-w-screen`, `max-w-screen` | `w-dvw`, `min-w-dvw`, `max-w-dvw` |
| `h-svh`, `w-svw` (and `min-`, `max-`) | `h-lvh`, `w-lvw` to keep the old size |

`*-full` on `top`, `right`, `bottom`, `left` or `inset` is `100%` now. Keep it when that was meant. Otherwise replace it with the px number the element needs.

For `object-*`, `isolate` and `collapse`, add the rules to `uno.config.ts`. Templates don't change:

```ts
rules: [
  [/^object-(contain|cover|fill|none|scale-down)$/, ([, v]) => ({ 'object-fit': v })],
  ['isolate', { isolation: 'isolate' }],
  ['collapse', { visibility: 'collapse' }],
],
```

Add only the ones the search found.

### 7. Block class names the project defines itself

**Check:** `uno.config.ts` blocks every class from the search below that the project styles itself.

Find the project's own classes that UnoCSS 3 also generates:

```bash
rg -nP --glob '!node_modules' --glob '!.nuxt' --glob '!.output' --glob '!dist' -g '*.{css,scss,sass,less,vue}' \
  '(?<![\w-])\.(container|flow|h[1-6]|border|outline|transition|transform|shadow|rounded|ring|tab|resize|contents|text-(xs|sm|base|lg|[2-9]?xl))(?![\w(-])'
```

Matches in scripts, such as `el.transform`, are fine. A scoped style doesn't help: the utility still adds the properties the project's class doesn't set. A project `.container` gets `container-type: inline-size` and a 932px maximum width, and a project `.h1` gets `height: 1px`.

Add each name to `blocklist` so UnoCSS skips it:

```ts
export default defineConfig<Theme>({
  presets: [presetOutloud({})],
  blocklist: ['container', /^h[1-6]$/],
})
```

Renaming the project's class is the other option. Step 9 shows any other class that started to generate CSS.

### 8. Fix classes that override each other

**Check:** each match below renders as it did in 2.

Elements with a display class and `hidden` or `grid`, or `inline-flex` and `flex-center`:

```bash
rg -nP --glob '!node_modules' --glob '!.nuxt' --glob '!.output' --glob '!dist' -g '*.{vue,html,tsx,jsx}' \
  'class="(?=[^"]*(?<![\w:-])(flex|inline-flex|flex-center)(?![\w-]))(?=[^"]*(?<![\w:-])(hidden|grid|inline-grid)(?![\w-]))|class="(?=[^"]*(?<![\w:-])flex-center(?![\w-]))(?=[^"]*(?<![\w:-])inline-flex(?![\w-]))'
```

- `flex hidden` was hidden in 2. When styles show the element later, such as on hover, remove `flex` and show it with `display: flex` in that style. When `hidden` was a leftover, remove it.
- `inline-flex flex-center` was inline. Replace `flex-center` with `justify-center items-center`.
- Matches in `:class` that pick one class or the other, such as `[open ? 'flex' : 'hidden']`, are fine.

Elements with an axis class and a side class of the same kind:

```bash
rg -nP --glob '!node_modules' --glob '!.nuxt' --glob '!.output' --glob '!dist' -g '*.{vue,html,tsx,jsx}' \
  'class="(?=[^"]*(?<![\w:-])([mp])y-[\w.]+)(?=[^"]*(?<![\w:-])\1[tb]-[\w.]+)|class="(?=[^"]*(?<![\w:-])([mp])x-[\w.]+)(?=[^"]*(?<![\w:-])\2[lr]-[\w.]+)'
```

In 2 the axis class won: `py-16 pt-8` had a top padding of 16px. Remove the side class to keep that, or keep it when its value is the one meant. Do the same for `border-x-*` or `border-y-*` with `border-l-*`, `border-r-*`, `border-t-*` or `border-b-*`.

Variants on `columns`, `flow` and `container`:

```bash
rg -nP --glob '!node_modules' --glob '!.nuxt' --glob '!.output' --glob '!dist' -g '*.{vue,html,tsx,jsx}' \
  '(?<![\w-])[\w~<>-]+:(columns|flow|container)(?![\w-])'
```

Replace `columns` with the classes it stood for in 2: `lt-lg:columns` becomes `lt-lg:grid lt-lg:grid-cols-12 lt-lg:gap-16`. Use the theme's `grid.columns` and `grid.gap` when they differ from 12 and 16.

### 9. Compare the generated CSS

**Check:** every line the diff shows is intended.

Write the new CSS with the command from step 1, to `uno-after.css`, and compare:

```bash
diff <(sort -u uno-before.css) <(sort -u uno-after.css)
```

- A line only in `uno-before.css` is a class 3 doesn't generate. Steps 6 to 8 should have replaced it.
- A line only in `uno-after.css` is a class that generated nothing before. Remove the class from the template when it wasn't meant to do anything, such as `text-sm`, `rounded`, `shadow`, `h1`, a dashless class like `mt8`, `hover:*` or a palette colour like `text-gray-500`. Add a name the project styles itself to `blocklist`.
- `.columns > *{grid-column:span 12 / span 12}` is new. Give each child of `columns` a `col-*` class when it should take less than the full row.
- These differences render the same and need nothing: `0rem` written as `0`, `aspect-ratio:1/1`, `-webkit-user-select`, `border-radius:9999px` for `rounded-full`, and hex colours written as `rgb(... / var(--un-bg-opacity))`.

Delete `uno-before.css` and `uno-after.css` afterwards.

### 10. Check the reset

**Check:** borders, placeholders and textareas look as they did, or the change is intended.

`@outloud/css/reset.css` is imported as before. Import it from CSS or the Nuxt `css` option, not from a script: `sideEffects: false` lets a bundler drop a script import.

To keep the old defaults, add to the project's base styles after the reset:

```css
:root {
  --un-default-border-color: currentColor;
}

textarea {
  resize: none;
}
```

Set a placeholder colour when the project relied on the browser's own, such as `::placeholder { color: GrayText; }`.

### 11. Verify

- Run the type check and build the project. No error mentions `toRem`, `toSize`, the theme or `presetOutloud`.
- Open the main pages. Spacing, sizes, colours and text render as before. Elements that show on hover or toggle are hidden until they should show. Buttons with `inline-flex` stay inline. Layouts using `container`, `columns` and `h1` to `h6` keep their width and height. Borders without a colour class have the colour they had before.
